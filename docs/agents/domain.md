# Domain docs

This repo uses a single-context layout:

- `GLOSSARY.md` at the repo root defines domain vocabulary.
- `docs/adr/` contains architecture decision records.

## Before exploring

Read the root glossary and ADRs relevant to the area being explored.
If these documents do not exist, continue silently.
The domain-modeling skill creates them when terms or decisions
are resolved.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and tests.
If a concept is missing, reconsider the term or record the gap
for domain-modeling.

## Decisions

If a proposal contradicts an ADR, identify the ADR and explain
why its decision should be reconsidered.
